# AGENTS.md

## 1. Общие правила

- Отвечай пользователю на русском языке.
- Пиши понятный, поддерживаемый и аккуратный код.
- Предпочитай простые решения сложным.
- Не усложняй архитектуру без объективной необходимости.
- Не добавляй функциональность, которую пользователь не запрашивал.
- Соблюдай существующий стиль проекта.

## 2. Перед началом работы

- Изучи структуру проекта и связанные файлы.
- Ознакомься с существующей архитектурой.
- Проверь используемые технологии и зависимости.
- Учитывай уже реализованные функции.
- Для сложных изменений сначала составь краткий план.
- Если требования неоднозначны и ошибка может существенно повлиять на результат, уточни их.

## 3. Работа с кодом

- Используй понятные названия переменных и функций.
- Избегай дублирования кода.
- Соблюдай принцип единственной ответственности.
- Не создавай ненужных абстракций.
- Не переписывай работающий код без необходимости.
- Не изменяй несвязанные с задачей участки проекта.
- Не оставляй неиспользуемый код.
- Добавляй комментарии там, где логика действительно требует пояснения.
- Учитывай обработку ошибок и пограничные случаи.

## 4. Сохранение существующего функционала

- Не удаляй рабочие функции без прямого запроса.
- Не изменяй утверждённый дизайн без согласования.
- Сохраняй совместимость существующих компонентов.
- Перед изменениями оценивай возможные побочные эффекты.
- Предпочитай минимальные точечные изменения.

## 5. Зависимости и архитектура

- Используй существующий технологический стек.
- Не устанавливай новые библиотеки без обоснования.
- Перед добавлением крупной зависимости согласуй решение.
- Не меняй фреймворк или архитектуру самостоятельно.
- Не создавай новые файлы и папки без необходимости.

## 6. Безопасность

- Не записывай секретные ключи и токены в исходный код.
- Используй переменные окружения для секретов.
- Не публикуй содержимое .env.
- Проверяй пользовательский ввод на сервере.
- Не добавляй небезопасные обходные решения.
- Не удаляй пользовательские данные без разрешения.

## 7. Проверка результата

После изменений:

- Проверь синтаксис изменённых файлов.
- Запусти существующие подходящие тесты.
- Проверь сборку, если она предусмотрена.
- Проверь отсутствие очевидных регрессий.
- Убедись, что изменения соответствуют задаче.
- Не утверждай, что тесты пройдены, если они не запускались.
- Сообщи об ошибках и проверках, которые не удалось выполнить.

## 8. Работа с ошибками

- Сначала установи причину ошибки.
- Не исправляй симптомы вместо причины.
- Не скрывай ошибки временными заглушками.
- Старайся устранить проблему минимальными изменениями.
- Проверяй, не появились ли новые ошибки.

## 9. Общение с пользователем

После выполнения задачи сообщай:

1. Что было изменено.
2. Какие файлы затронуты.
3. Какие проверки выполнены.
4. Что осталось сделать, если задача не завершена.

- Не заявляй о завершении без проверки результата.
- Объясняй сложные технические решения простым языком.
- Предлагай улучшения отдельно, не внедряя их самовольно.

## 10. Запрещённые действия

- Не удаляй большие части проекта без разрешения.
- Не меняй согласованный технологический стек.
- Не подменяй реальные данные вымышленными.
- Не отключай проверки ради успешной сборки.
- Не добавляй лишнюю функциональность.
- Не выполняй необратимые операции без подтверждения.
- Не делай коммиты и push без прямого запроса.

## 11. Главный принцип

Выполняй поставленную задачу полностью,
сохраняй работающий функционал,
не вноси лишних изменений
и проверяй результат перед завершением.
